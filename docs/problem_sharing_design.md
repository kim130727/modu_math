# 문제 공유와 클래스 설계

## 서비스가 이어지는 방식

선생님이 좋은 문제를 만들고 공개하면 학생은 클래스에 가입하지 않아도 로그인 후 자유롭게 풀 수 있습니다. 선생님은 공개 문제 중 수업 사용이 허용된 문제와 직접 만든 문제를 모아 문제집을 만들고, 자신의 클래스에 과제로 배정합니다.

클래스는 선생님과 학생이 만나는 독립적인 학습 그룹입니다. 한 선생님이 여러 클래스를 운영할 수 있고, 한 학생도 여러 클래스에 참여할 수 있습니다. 클래스마다 가입 승인, 공유 문제, 과제, 결과를 관리합니다. 다른 클래스의 학생 명단과 학습 기록은 공개되지 않습니다.

## 선생님이 보는 화면

1. 교사 계정으로 로그인합니다. 현재 교사 권한은 기존 관리자 승인 절차를 유지합니다.
2. 웹 에디터에서 새 문제를 만듭니다. 처음에는 **초안 · 나만 보기**로 저장됩니다.
3. 문제와 정답을 확인하고 저장·빌드합니다. 빌드 결과는 같은 소유자의 문제은행 기록에 연결됩니다.
4. **공개 범위 설정**에서 누구에게 보여줄지 선택합니다.
5. 학생에게 제공할 준비가 끝나면 작업 상태를 **사용 가능**으로 변경합니다.

문제은행에는 **함께 쓰는 문제은행 / 내가 만든 문제 / 모두에게 공개된 문제**를 제공합니다. 목록에서 작성자, 공개 범위, 작업 상태를 함께 확인할 수 있습니다. 문제 작성자와 관리자는 공개 설정을 변경할 수 있습니다. 다른 선생님은 공개되었다는 이유만으로 원본을 수정할 수 없습니다.

| 공개 범위 | 학생의 자유 학습 | 다른 선생님의 사용 |
| --- | --- | --- |
| 나만 보기 | 공개 목록에서 보이지 않음. 배정받은 과제로는 풀이 가능 | 검색·열람·사용 불가 |
| 선택한 클래스 | 선택된 클래스에서 가입이 승인된 학생만 자유 학습 가능 | 검색·열람·사용 불가 |
| 모두에게 공개 | 클래스 가입 없이 모든 학생이 자유 학습 가능 | 작성자가 수업 사용을 허용한 경우 문제집·과제에 사용 가능 |

공개 범위와 작업 상태는 독립적입니다. **초안 / 검수 중 / 사용 가능 / 보관** 중 사용 가능인 문제만 학생의 공개·클래스 문제 목록에 나타납니다. 소유자는 초안을 보며 작업할 수 있습니다.

**다른 선생님의 수업 사용 허용**은 문제를 참조하여 문제집·과제를 구성하는 권한입니다. 원본 소유권 이전이나 편집 가능한 원본 복제 권한을 의미하지 않습니다. 편집 가능한 사본 생성은 현재 제공하지 않습니다.

## 학생이 보는 화면

- **내 과제**: 선생님이 배정한 문제를 풀고, 정해진 시점에 평가 결과를 확인합니다.
- **공개 문제 · 내 클래스**: 모두의 공개 문제와 가입이 승인된 클래스의 공유 문제를 선택합니다. 학년으로 필터링하고 페이지를 넘겨 탐색합니다.
- **자유롭게 풀기**: 문제, 작성자, 출처, 이용 조건을 보고 답을 제출합니다. 서버에서 채점한 결과를 표시하고 기존 학습 시도·숙련도 집계에 기록합니다.
- 가입 승인 대기 중인 클래스는 대기 상태를 표시하며 공유 문제에 접근할 수 없습니다.

자유 학습은 과제의 정답 공개 정책을 우회할 수 없습니다. 같은 문제가 미제출 과제에 포함되어 있거나 결과 공개 시점이 되지 않았다면 기존 과제 제출 규칙을 적용합니다.

## 클래스 만들기와 참여

선생님은 기존 학급 관리 화면에서 클래스를 만들고 초대 코드를 전달합니다. 학생이 코드로 가입하면 선생님이 승인합니다. 승인 후 클래스 공유 문제를 자유롭게 풀 수 있고, 클래스 단위로 과제를 배정받을 수 있습니다.

공개 문제를 풀기 위한 클래스 가입은 필요하지 않습니다. 클래스를 탈퇴 처리하거나 비활성화하면 해당 클래스의 자유 학습 접근도 사라집니다. 클래스를 보관하면 클래스 목록과 클래스 공유 문제의 신규 접근이 차단됩니다. 이미 배정된 과제는 별도 수명주기를 유지합니다.

## 출처와 공개 철회

- 출처·권리자와 이용 조건을 입력합니다. 학생의 문제 화면과 과제 스냅샷에도 보존합니다.
- 클래스 또는 전체 공개를 선택할 때 공유할 권한이 있는지 확인합니다. 이 확인은 권리 심사를 대신하지 않습니다.
- 전체 공개에서 비공개로 변경하면 새 목록 조회, 상세 조회, 추천, 일반 답안 제출, 다른 선생님의 새 문제집·과제 사용을 차단합니다.
- 기존에 만들어 둔 타 교사의 문제집도 새로 배정하거나 복제할 때 권한을 다시 검사합니다.
- 이미 배정된 과제는 배정 시점의 문제·출처 스냅샷을 유지합니다. 학생의 과제와 평가 기록을 보존하기 위한 정책입니다.
- 이미 전달된 화면이나 캡처를 회수하지는 않습니다. 모든 기존 배정의 즉시 중단은 별도의 운영 기능이 필요합니다.

## 서버와 데이터

`ProblemPublication`에 소유자, 원본 경로, 공개 범위, 공유 클래스, 수업 사용 허용, 출처, 이용 조건, 권리 확인을 저장합니다. 문제 DSL·렌더러 계약에는 계정 권한을 넣지 않습니다.

`learning/services/problem_access.py`가 공개·클래스 접근과 수업 사용 규칙을 관리합니다. 목록뿐 아니라 상세, 이미지, 답안 제출, 추천, 문제집 구성·복제, 과제 배정에 적용합니다. 학생에게 정답·원본 DSL을 전달하지 않고 서버에서 채점합니다.

웹 에디터는 원본 파일을 실제 소유자의 문제와 연결하여 조회·수정 권한을 검사합니다. 새 파일은 작성자별 독립 디렉터리에 저장합니다. 원본 편집 API와 파일 접근은 운영 환경에서 교사 인증과 소유권 확인을 모두 거칩니다. 로컬 개발의 익명 에디터 예외는 기존 `DEBUG=True` 정책을 유지하므로 학생 서비스는 반드시 `DEBUG=False`로 운영합니다.

학생용 새 문제 탐색 화면은 문제 데이터를 디스크에 저장하거나 앱에 번들로 넣지 않습니다. 서버는 문제·에디터·학생 API에 `private, no-store`를 적용합니다. 운영 앱은 기존 `prepare_student_build.py` / `build_student_web.py` 경로를 사용하여 개발용 문제 번들을 제외해야 합니다.

추가 API:

- `GET /api/v1/problems/?scope=public|mine|class` — 사용자 권한 내 문제 탐색
- `GET /api/v1/problems/?scope=class&classroom=<id>` — 승인받은 클래스 문제 탐색
- `GET /api/v1/student/classes/` — 본인의 클래스와 가입 상태
- `GET/PATCH /api/v1/problems/<id>/publication/` — 소유자의 공개 설정
- `GET/PATCH /api/editor/problems/<source>/publication/` — 에디터의 공개 설정

## 기존 데이터와 적용

`python manage.py migrate`로 `0006_problem_visibility`까지 적용합니다. 기존 게시된 문제는 공개·수업 사용 가능 상태를 유지하고, 새 문제는 비공개가 기본값입니다. 기존에 소유자 기록이 없던 문제는 공식 문제로 유지하며 관리자가 관리합니다. 작성자가 확인되지 않은 과거 문제를 임의의 교사에게 자동 귀속하지 않습니다.

`sync_problems`는 이미 연결된 문제의 소유권과 공개 범위를 덮어쓰지 않습니다. 신규 가져오기는 기본 비공개이며, 운영자가 명시적으로 공개하려면 `--new-status published --new-visibility public`을 사용합니다. 서로 다른 원본이 같은 문제 ID를 덮어쓰려는 경우 오류로 중단합니다.

## 참여가 늘어난 다음 단계

교사 가입 신청·승인, 공개 문제 신고·검토, 작성자 프로필과 공개 문제 모음, 교사 간 지정 공유, 편집 가능한 사본의 별도 허락과 원저작자 연결을 후속 단계로 확장할 수 있습니다. 공개 문제 수나 풀이 수는 기여 지표로 활용할 수 있지만 학생 개인의 성적과 클래스 명단은 공개 지표에 포함하지 않습니다. 이 단계의 기능들은 이번 구현에 포함하지 않았습니다.

교사 가입을 누구에게나 자동 승인하는 단계에서는 원본 Python DSL 빌드의 실행 격리도 함께 도입해야 합니다. 현재 빌드는 기존과 같이 승인된 교사의 원본을 실행하는 구조이며, 이번 변경은 문제별 데이터 접근 권한을 추가한 것입니다.
