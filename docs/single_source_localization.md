# 한국어 DSL을 원본으로 사용하는 다국어 편집

문제의 Python 원본은 `examples/problems/ko/*.dsl.py`에만 보관합니다.
영어·일본어·중국어·우크라이나어·크메르어는 같은 이름의
`*.locale-delta.json`에 한국어 원본과 다른 필드만 저장합니다.
기존 번역 문구, 풀이, 정답 설정, 튜터 흐름, 언어별 배치 차이를 보존합니다.

## 웹에디터 사용법

1. 한국어 탭에서 원본 문제를 편집하고 저장합니다.
2. 언어 탭을 선택하면 원본과 해당 언어의 차이를 합친 문제가 열립니다.
3. 번역 문구나 해당 언어의 배치를 수정하고 저장합니다.
4. Build를 실행하면 선택 언어의 SVG와 JSON이 생성됩니다.
   한국어 문제를 Build하면 연결된 번역 문제도 갱신됩니다.

한국어 원본의 공통 필드는 모든 언어가 상속합니다. 언어별로 다르게
저장된 필드는 해당 언어의 값이 우선합니다. 기존 언어별 배치 보정도
보존하므로 특정 언어에서 따로 조정한 위치는 공통 위치보다 우선합니다.
원문이 바뀐 번역은 문제를 열 때 검토 안내가 표시됩니다.
구조 변경으로 번역 대상 필드를 찾을 수 없으면 잘못된 위치에 적용하는 대신
명시적인 오류를 반환합니다.

API의 `en/문제명.dsl.py` 같은 문제 ID는 호환성을 위해 유지하지만,
그 경로에 실제 Python 파일을 만들지 않습니다. DSL 편집 화면의 코드는
메모리에서 합성하며, 저장 시 차이 데이터로 환원합니다.
빠른 캔버스 편집의 `editor_overrides.json`과 생성된 SVG/JSON은 계속 사용합니다.
`locales/`의 기존 번역 카탈로그도 보존하며 자동으로 이중 갱신하지 않습니다.
이미 통합된 문제에 번역 적용 도구를 다시 실행하면 Python 파일을 재생성하지
않고 차이 데이터를 갱신합니다.

## 이전 및 검증

```powershell
.venv\Scripts\python.exe tools/migrate_dsl_variants.py examples/problems
.venv\Scripts\python.exe tools/migrate_dsl_variants.py examples/problems --delete
```

첫 명령은 번역 Python을 남겨 둔 채 차이 데이터를 생성하고 데이터 및
합성 코드의 왕복 일치를 검증합니다. 두 번째 명령은 모든 대상의 검증이
통과한 뒤 번역 Python만 삭제합니다. 원본이 없는 파일은 오류로 처리합니다.
운영 파일 이전 전에 SVG/JSON 결과 비교와 웹에디터 테스트도 실행해야 합니다.

한국어 폴더·임시 초안·보관소 DSL은 삭제 대상이 아닙니다.
기존 PowerShell 감시/폴더 빌드 도구는 실제 Python 파일을 탐색하므로
통합된 번역의 빌드는 웹에디터를 사용합니다.
